## 4. Deploy em produção (concluído nesta semana)

### Stack de produção
| Serviço | Provedor | URL |
|---|---|---|
| **API (NestJS)** | Railway | `https://api-production-ca5d.up.railway.app` |
| **Frontend (Next.js)** | Vercel | `https://nexly-web.vercel.app` |
| **PostgreSQL (RLS)** | Supabase | sa-east-1 |
| **Redis** | Upstash | gru1 |

### Correções de deploy feitas ao longo do caminho
| Problema | Correção |
|---|---|
| `tsc: not found` (Railway) | `nixpacks.toml` + `npm ci --include=dev` |
| `EBUSY` (npm ci duplicado) | removido do buildCommand |
| Prisma Client desatualizado (104 erros) | `prebuild: prisma generate` |
| `NODE_ENV` vazio (zod crash) | `preprocess` no `env.ts` |
| `turbo run build` no Vercel | `buildCommand` = `next build` |
| `@nexly/shared` não encontrado | builda shared antes |
| `Can't resolve 'path'` (opengraph) | `runtime = 'nodejs'` |
| CORS bloqueando (429 sem headers) | CORS movido para antes do rate limit |
| Login 200 mas não abria a conta | `AuthGuard` client-side (cookie da API não é lido pelo middleware do frontend) |

### Verificação final em produção (confirmado)
- ✅ `GET /api/health` → 200
- ✅ `GET /api/health/deep` → db + redis `ok`
- ✅ `POST /api/auth/login` → JWT RS256 + usuário
- ✅ Login no frontend → redireciona para o dashboard

## 6. Segurança (auditoria + correções aplicadas)

### Correções críticas feitas
| # | Falha | Correção |
|---|---|---|
| 1 | RBAC não aplicado no backend (qualquer role acessava tudo) | `PermissionsGuard` por `recurso:acao` |
| 2 | IDOR em troca de senha | usa `id` do usuário autenticado |
| 3 | Bug `user.sub` vs `user.id` | corrigido em me/2fa/lgpd |
| 4 | CORS antes do rate limit (429 sem headers) | reordenado |
| 5 | Cookie cross-site | `SameSite=None; Secure` em produção |

### Pendências de segurança (não-bloqueantes)
- **Dependências vulneráveis** (`npm audit`: 1 critical + 5 high no Next.js 14, PostCSS, js-yaml, lodash, multer) — upgrade do Next é breaking change.
- **CSP** com `unsafe-inline`/`unsafe-eval` (necessário para o Next hydration).
- **E-mail/WhatsApp reais** ainda com provedores simulados (`test`/`disabled`).
